# Buyer Service

Этот сервис предназначен для пользования покупателями. Здесь покупатели регистрируются, ищут товары, добавляют в корзины и непосредственно совершают покупки.

**Имя БД:** `buyer_database`
**Схема:** `buyer_application`

## Архитектура безопасности

Подразумевается, что авторизация и аутентификация пользователей будет реализована в отдельном сервисе.

Запросы к buyer-service и seller-service не будут поступать непосредственно, они будут проксироваться через gateway_service.

**Последовательность:**
1. В gateway_service пользователь (покупатель или продавец) авторизируется и аутентифицируется, выполняет нужный ему запрос;
2. gateway_service направляет запрос в нужный сервис, обогащая его хэдером `X-Auth-User-ID`, куда помещается UUID пользователя;
3. При обработке запроса данные о пользователе берутся из хэдера `X-Auth-User-ID`.

Хэдер `X-Auth-User-ID` не добавляется для эндпоинтов, которые работают с записями пользователей: добавляют, изменяют, получают список пользователей или данные по конкретному пользователю. Предполагается изначально, что эти запросы будут приходить от администрации, у простых пользователей не будет возможности через gateway_service отправить эти запросы (такой подход не вполне верен и в реальном проекте нам следовало бы создать ещё и сервис для администрации, но времени на это едва ли хватит).

## Принцип работы сервиса

- Администрация добавляет новый товар в seller-service, оттуда перенаправляется запрос на создание товара;
- Через REST или Kafka (сперва будет только REST) продавец добавляет предложение;
- Покупатель ищет предложения, добавляет в корзину;
- Покупатель совершает заказ, покупая товары из корзины. Происходит подсчёт стоимости, происходит проверка наличия товаров на складе (покупатель мог положить в корзину товар, когда его было достаточно, однако его могли разобрать). Информация о заказе отправляется в order_service, где непосредственно производится оплата (order_service реализовывать в данном проекте не будем, просто добавим заглушку).
